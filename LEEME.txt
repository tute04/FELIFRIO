FELIFRÍO 1.6 · NUBE (SUPABASE)

La versión web se conecta a Supabase y guarda clientes, movimientos, caja y stock por cuenta autenticada.

INICIO DE SESIÓN
1. Abrí la web publicada en Vercel.
2. Seleccioná "Crear cuenta", ingresá correo y contraseña.
3. Si pide confirmación, revisá el correo; luego iniciá sesión.
4. Ingresá con LA MISMA CUENTA en el celular y en la computadora.

MIGRAR DATOS ANTERIORES
1. Antes de cambiar de versión, descargá un respaldo JSON desde la app anterior.
2. Una vez iniciada la sesión en la versión 1.6, hacé clic en "Importar respaldo JSON".
   También podés usar "Detectar datos anteriores" si los registros locales pertenecen al mismo navegador y dominio.
3. Revisá la cantidad de clientes y movimientos. Confirmá la importación a Supabase.
4. Por seguridad, la importación se bloquea si la nube YA contiene movimientos; nunca fusiona ni reemplaza registros en forma automática.
5. Guardá el respaldo JSON fuera de GitHub, por ejemplo en una carpeta privada.

USO NORMAL
- Las ventas, las consignaciones, los cobros y las ediciones se guardan directamente en Supabase.
- El botón "Descargar respaldo" permite exportar una copia de seguridad en JSON.
- El dispositivo necesita Internet para registrar modificaciones.
- Sin conexión se puede consultar una última copia previamente descargada, pero NO registrar cambios. El modo sin conexión NO es una cola de sincronización.
- Si dos equipos intentan guardar sobre datos desactualizados, la app pedirá actualizar antes de confirmar.

SEGURIDAD
- Supabase Auth se encarga del ingreso con correo y contraseña.
- Las tablas tienen políticas RLS para limitar los datos a cada cuenta.
- La clave incluida en index.html es una clave PUBLICABLE, nunca una service_role.
- Asegurate de configurar en Supabase -> Authentication -> URL Configuration la dirección real de tu sitio en Vercel como Site URL y redirect permitido, para la confirmación por email.
- Para dos o más usuarios que deban compartir LA MISMA empresa con cuentas diferentes aún se necesita crear un sistema de empresas/permisos. Por ahora cada cuenta tiene su propio espacio.
- No subas nunca contraseñas, JSON de respaldo ni claves secretas a GitHub.
